# 8. Words and software explained

Use this page as a dictionary. You do not need to memorize every package: the main learning tools are scikit-learn, MiniLM and ClinicalBERT.

## Project vocabulary

| Word | Plain meaning |
| --- | --- |
| Case / instance / record | One example to classify |
| Label / gold | The supplied expected answer |
| Class | One of the 12 specialties |
| Feature | A number representing some property of the text |
| Representation | The way a case is turned into numbers |
| Lexical | Based on words or letter patterns |
| Metadata | Extra information about a case, such as keywords |
| Corpus | The collection of texts |
| Fitting / training | Learning from examples |
| Validation / development | Examples used to choose settings |
| Internal / outer test | Held-out labelled cases used to measure the frozen choice |
| Official test | The separate unlabelled file used for the submission output |
| Parameter | A value learned during fitting, such as a word weight |
| Hyperparameter | A setting chosen outside fitting, such as SVM C |
| Tuning | Trying settings and comparing validation results |
| Seed | A number that controls random choices for repeatability |
| Fold | One part of a partition used by a splitter |
| Group | Cases sharing a normalized note key |
| Stratified | Split with attention to class proportions; grouped constraints can limit exact matching |
| Leakage | Held-out information influencing fitting or selection |
| Bare model | Model predictions without added decision rules |
| Full system | Model plus the selected input condition and rules |
| Policy | Which decision rules to apply |
| Route | Which part of the system decided a particular case |
| Ablation | A comparison where an input or component is changed or removed |
| Memorisation rate | For repeated notes here, how often a bare model predicts a fitting copy's label |
| Augmentation | Add variants or copies to fitting examples |
| Resampling | Repeat examples to change their influence |
| Dropout here | Remove input fields from some training variants; different from neural layer dropout |
| Donor | The fitting case supplying a replacement section |
| Lineage / provenance | Saved information about where data or predictions came from |
| OOF | Out-of-fold: predicted by a fold model that did not fit on that case |
| Minority class | A class with relatively few examples |
| Balanced weights | Increase the relative fitting influence of small classes |
| Token / word piece | A piece of text processed by an encoder, possibly part of a word |
| N-gram | A sequence of n words or characters |
| Stemming | Reduce word endings to a common stem |
| TF-IDF | Weight text features using within-case frequency and rarity across fitting cases |
| Sublinear TF | Make repeated-word counts grow more slowly, using a logarithm |
| min_df | Minimum number of fitting documents containing a feature |
| max_features | Limit on how many vocabulary features are retained |
| Vector | An ordered list of numbers |
| Sparse vector | A vector with mostly zero entries |
| Dense embedding | A compact text vector whose values are learned by a representation model |
| Normalize | Rescale a vector so its length is controlled |
| Pool / average | Combine several chunk vectors into one field vector |
| Frozen | Pretrained weights stay unchanged |
| Fine-tune | Adapt pretrained weights to this labelled task |
| Pretrained | Learned before this project on other data |
| Epoch | One pass through fitting cases |
| Checkpoint | A saved model state at a point during training |
| Batch / microbatch | A small group of examples processed together |
| Gradient | Numerical direction used to update learned parameters |
| Gradient accumulation | Combine small-batch gradients before one update |
| Loss | A numerical measure of fitting mistakes |
| Learning rate | Size of a neural update step |
| Weight decay | A penalty discouraging unnecessarily large neural weights |
| Warm-up | Gradually increase the learning rate early in training |
| C | Inverse regularization setting; higher values penalize fitting errors more strongly |
| Bootstrap interval | Repeatedly resample groups to describe score variation |
| Empirical bound | A limit calculated for the observed data under specified input restrictions |
| Hash / SHA-256 | A fingerprint used to identify text or detect file changes |
| Revision | Exact saved version of a pretrained model |
| Manifest | Structured record of the chosen system and its selection |
| Artifact | A file generated by an experiment |
| CPU | Main processor; used for our sparse learners |
| GPU / MPS | Apple graphics computation used for neural models when available |

For precision, recall, F1 and accuracy, see [lesson 4](04_RESULTS_AND_QUESTION.md).

## Programs and file formats

| Tool or format | Purpose here |
| --- | --- |
| Python | Programming language running the data/model scripts |
| pip | Installs the required Python packages |
| Shell / terminal | Runs commands; the launchers use `sh` |
| Virtual environment (.venv) | A local Python installation with this project's packages |
| Git / .gitignore | Track code changes and ignore machine-generated files |
| Black | Reformatted Python code in earlier preparation; not a model or required classifier |
| Markdown (.md) | Readable draft and study-note format |
| JSON (.json) | Named settings and measured results in text form |
| CSV (.csv) | Rows/columns of cases, predictions or donor histories |
| NPZ (.npz) | Compressed numerical arrays, such as 12 class scores per case |
| PNG (.png) | An image, used for the confusion matrices |
| Log (.log) | Captured terminal output from a run |
| PYC / __pycache__ | Automatic compiled Python copies; learn from the source instead |
| LaTeX / .tex | Typeset the final paper using the supplied template |
| PDF | Final readable paper required by the professor |
| ZIP | Archive bundling paper, code, data and predictions |
| Fenix | Platform where the group manually submits the archive |
| Hugging Face Hub | Hosts pretrained model files downloaded for the comparisons |

“LLM assistance” means help with design, code, review and writing. MiniLM and ClinicalBERT are pretrained classification representations in the experiment; the assistant does not manually supply the 409 case labels.
